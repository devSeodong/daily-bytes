# 티스토리 블로그 GEO 세팅기: ChatGPT·Perplexity 같은 AI 검색에 잘 잡히게 만들기

> 🧪 **AI 활용** · 2026-11-26 · 📝 [티스토리에서 보기](https://dongseodong.tistory.com/67)

![대표 이미지](assets/2026-11-26-tistory-geo-setup.png)

요즘은 검색창에 키워드를 치는 대신 ChatGPT나 Perplexity 같은 AI에게 바로 묻는 경우가 많아졌어요. 그러면 AI가 웹에서 글을 찾아 읽고, 답변 아래에 출처로 링크를 달아 줘요. 그 출처 자리에 내 블로그 글이 들어가게 만드는 작업을 **GEO(Generative Engine Optimization)** 라고 불러요.

이 블로그는 매일 AI·개발 소식을 세 편씩 올리고 있어서, 사람이 검색해서 들어오는 것만큼 AI가 읽고 인용해 주는 것도 중요하다고 생각했어요. 그래서 Claude와 함께 블로그 상태를 점검하고, 스킨과 글 구조를 고치고, 검색엔진 등록까지 하루 만에 끝냈어요. 이 글은 그 순서를 그대로 정리한 기록이에요. 티스토리 블로그라면 거의 그대로 따라 할 수 있어요.

TL;DR · 한눈에 보기

1 먼저 점검: robots.txt, 사이트맵, 구조화 데이터, 메타 설명, 제목 태그를 확인했어요.

3 등록과 글 구조: 구글·Bing·네이버에 사이트를 등록하고, 매일 글 끝에 FAQ를 붙이기로 했어요.

## 01 GEO는 SEO와 뭐가 다를까

**한 줄 요약:** SEO가 "검색 결과 목록에 잘 뜨기"라면, GEO는 "AI가 만든 답변 안에 출처로 인용되기"예요.

| 구분      | SEO                       | GEO                                                                   |
|-----------|---------------------------|-----------------------------------------------------------------------|
| 목표      | 검색 결과 상위 노출, 클릭 | AI 답변에 인용, 출처 링크                                             |
| 읽는 쪽   | 검색엔진 크롤러 → 사람    | 검색엔진 색인 + AI 크롤러 → AI → 사람                                 |
| 중요한 것 | 키워드, 링크, 페이지 속도 | 크롤링 허용, 구조화 데이터, 질문에 바로 답하는 문장, 명확한 날짜·출처 |

둘은 따로 노는 게 아니에요. AI 검색도 결국 기존 검색엔진 색인과 자체 크롤러로 글을 찾기 때문에, 기본 SEO가 돼 있어야 GEO도 효과가 있어요. 그래서 기본기 점검부터 시작했어요.

## 02 1단계: 지금 상태부터 점검하기

**한 줄 요약:** 고치기 전에 AI 크롤러가 막혀 있지 않은지, 검색엔진이 읽을 정보가 비어 있지 않은지 확인했어요.

### robots.txt와 AI 크롤러

먼저 AI 회사들의 크롤러가 막혀 있는지 봤어요. 티스토리는 robots.txt를 직접 관리하고 블로그 주인이 고칠 수 없어서, 확인만 하면 돼요.

▶ robots.txt 확인 (내 블로그 주소로 바꿔서)

```
curl -s https://dongseodong.tistory.com/robots.txt
```

| 크롤러 이름     | 회사       | 점검 결과 |
|-----------------|------------|-----------|
| GPTBot          | OpenAI     | 허용      |
| ClaudeBot       | Anthropic  | 허용      |
| PerplexityBot   | Perplexity | 허용      |
| Google-Extended | Google     | 허용      |

이 블로그의 robots.txt는 `User-agent: *`에 관리 화면, 검색, 방명록 같은 경로만 막고 있었고, 위 크롤러를 따로 막는 줄은 없었어요. 사이트맵(`/sitemap.xml`, 점검 당시 165개 URL)과 RSS(`/rss`)도 정상이었어요.

### 구조화 데이터와 메타 태그

다음은 글 페이지 HTML 안에 검색엔진용 정보가 있는지 봤어요.

▶ 글 페이지의 JSON-LD, description, h1 확인

```
URL=https://dongseodong.tistory.com/62
curl -s $URL | grep -o '<script type="application/ld+json">[^<]*' | head -c 600; echo
curl -s $URL | grep -o '<meta name="description"[^>]*>'
curl -s $URL | grep -o '<h1[^>]*>[^<]*' | head
```

| 항목                   | 점검 결과                                                  | 조치                     |
|------------------------|------------------------------------------------------------|--------------------------|
| 글 BlogPosting JSON-LD | 티스토리가 제목, 작성자, 날짜, 이미지를 자동으로 넣고 있음 | 그대로 둠                |
| 작성자·블로그 정보     | 작성자와 GitHub 등 외부 프로필이 연결돼 있지 않음          | JSON-LD 추가 (2단계)     |
| 글 제목 태그           | h1이 블로그 이름이고, 글 제목은 h2                         | 글 제목을 h1로 (3단계)   |
| 홈 description         | 블로그 설명이 비어 있어서 빈칸                             | 블로그 설명 입력 (4단계) |
| 검색엔진 소유확인      | 구글·Bing·네이버 모두 없음                                 | 등록 (5단계)             |

📌 점검을 먼저 한 이유

티스토리가 이미 해 주는 것(BlogPosting, 사이트맵, RSS)을 모르고 또 넣으면 같은 정보가 두 번 들어가서 오히려 헷갈리게 돼요. 이미 있는 건 두고, 비어 있는 것만 채우기로 했어요.

## 03 2단계: 스킨에 작성자·블로그 JSON-LD 넣기

**한 줄 요약:** "이 블로그는 누가 쓰고, 그 사람은 어디서 활동하는지"를 기계가 읽을 수 있게 스킨 head에 적었어요.

AI 답변은 출처의 신뢰도를 따질 때 작성자 정보를 참고할 수 있어요. 그래서 Person(작성자)과 Blog(블로그) 정보를 `@graph` 하나에 묶고, `sameAs`로 GitHub 프로필을 연결했어요. 매일 글을 마크다운으로 쌓는 [daily-bytes](https://github.com/devSeodong/daily-bytes) 레포도 함께 연결했어요.

STEP 1

관리 → 꾸미기 → 스킨 편집 → **html 편집**

STEP 2

바꾸기 전 HTML과 CSS 전체를 복사해서 백업

STEP 3

`</head>` 바로 앞에 아래 블록 붙여 넣고 저장

▶ \</head\> 앞에 넣은 블록 (이름·주소는 내 것으로)

```
<!-- sd: geo -->
<meta name="author" content="내 이름">
<link rel="author" href="https://github.com/내아이디">
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "Person",
      "@id": "https://내블로그.tistory.com/#author",
      "name": "내 이름",
      "url": "https://내블로그.tistory.com/",
      "sameAs": ["https://github.com/내아이디"]
    },
    {
      "@type": "Blog",
      "@id": "https://내블로그.tistory.com/#blog",
      "name": "블로그 이름",
      "url": "https://내블로그.tistory.com/",
      "inLanguage": "ko-KR",
      "author": {"@id": "https://내블로그.tistory.com/#author"},
      "isBasedOn": "https://github.com/내아이디/아카이브레포"
    }
  ]
}
</script>
<!-- /sd: geo -->
```

앞뒤에 `<!-- sd: geo -->` 주석을 달아 둔 건 나중에 찾거나 지우기 쉽게 하려고요. 저장 후에는 [구글 리치 결과 테스트](https://search.google.com/test/rich-results)나 [Schema Markup Validator](https://validator.schema.org/)에 블로그 주소를 넣어 오류가 없는지 확인하면 돼요.

## 04 3단계: 글 제목을 h1으로 바꾸기

**한 줄 요약:** 글 페이지에서 가장 중요한 제목(h1)이 블로그 이름이 아니라 글 제목이 되게 했어요.

많은 티스토리 스킨이 모든 페이지에서 블로그 이름을 h1으로 쓰고, 글 제목은 h2로 둬요. 사람 눈에는 차이가 없지만, 기계가 "이 페이지의 주제"를 읽을 때는 h1을 먼저 봐요. 스킨 HTML에서 글 본문 영역(`s_article_rep`) 안의 제목 태그만 바꿨어요.

▶ 스킨 HTML의 글 제목 부분 (스킨마다 class 이름은 다를 수 있어요)

```
- <h2 class="title-article">(글 제목 치환자)</h2>
+ <h1 class="title-article">(글 제목 치환자)</h1>
```

⚠ 모양이 바뀌는지 확인

h1과 h2는 기본 글자 크기가 달라서, CSS가 태그 이름(h2)으로 스타일을 주고 있었다면 제목 모양이 바뀔 수 있어요. 이 블로그 스킨은 class로 스타일을 줘서 화면은 그대로였어요. 페이지·공지 같은 다른 화면의 제목은 건드리지 않았어요.

## 05 4단계: 블로그 설명 채우기

**한 줄 요약:** 관리 → 블로그 설정의 "블로그 설명"이 홈 화면의 description이 돼요.

이게 비어 있으면 홈 화면의 `meta description`과 `og:description`이 빈칸으로 나가요. 검색 결과와 링크 미리보기, 그리고 AI가 "이 블로그는 뭘 다루는 곳인지" 파악할 때 쓰는 문장이라 짧고 구체적으로 적었어요.

> 매일 AI 이슈, AI 트렌드, CS·개발 이슈를 출처와 함께 정리하는 개발 블로그

▶ 저장 후 홈 화면 description 확인

```
curl -s https://dongseodong.tistory.com/ | grep -o '<meta[^>]*description[^>]*>'
```

## 06 5단계: 구글·Bing·네이버에 사이트 등록하기

**한 줄 요약:** 세 곳 모두 10분 안에 끝나요. 구글을 먼저 하면 Bing은 가져오기 한 번이면 돼요.

| 순서                    | 어디서                   | 방법                                                                                     |
|-------------------------|--------------------------|------------------------------------------------------------------------------------------|
| ① 구글 서치 콘솔        | 티스토리 관리 → 플러그인 | **구글 서치콘솔** 플러그인에서 구글 계정 연결. 사이트 등록과 사이트맵 제출이 자동으로 됨 |
| ② Bing 웹마스터 도구    | bing.com/webmasters      | **Import from Google Search Console** 로 ①의 사이트와 사이트맵을 그대로 가져옴           |
| ③ 네이버 서치어드바이저 | searchadvisor.naver.com  | 사이트 등록 → HTML 태그 방식 소유확인 → 사이트맵·RSS 제출                                |

### Bing을 꼭 챙긴 이유

OpenAI는 ChatGPT 검색이 Microsoft Bing 같은 외부 검색 제공자를 활용한다고 밝혔어요. 그래서 구글에만 등록하고 끝내지 않고, 가져오기 기능으로 Bing에도 같이 등록했어요. 구글에서 가져오면 추가로 할 일이 거의 없어요.

### 네이버 소유확인 태그 넣기

네이버는 HTML 태그 방식으로 소유를 확인해요. 받은 `<meta name="naver-site-verification" ...>` 태그를 스킨 head(2단계에서 만든 `sd: geo` 블록 안)에 넣고, 홈 화면에 태그가 나오는지 확인한 뒤 **소유확인** 을 눌렀어요.

▶ 소유확인 태그가 실제로 나오는지 확인

```
curl -s https://dongseodong.tistory.com/ | grep -o '<meta name="\(google\|naver\)-site-verification"[^>]*>'
```

소유확인이 끝나면 **요청 → 사이트맵 제출** 에 `https://내블로그.tistory.com/sitemap.xml`을, **요청 → RSS 제출** 에 `https://내블로그.tistory.com/rss`를 넣으면 돼요.

📌 소유확인 코드는 공개해도 될까

소유확인 태그는 어차피 블로그 HTML에 공개로 들어가는 값이라 비밀번호 같은 비밀은 아니에요. 그래도 글이나 스크린샷에 일부러 올릴 이유는 없어서, 이 글에는 넣지 않았어요.

## 07 6단계: 글 자체를 AI가 인용하기 좋게

**한 줄 요약:** 질문에 바로 답하는 문장, 명확한 날짜와 출처, 글 끝 FAQ를 매일 글 규칙에 넣었어요.

스킨을 아무리 고쳐도 결국 인용되는 건 글의 문장이에요. AI는 질문에 딱 맞는 짧은 답을 찾아서 가져가기 때문에, 그런 문장이 글 안에 분명하게 있어야 해요. 그래서 2026년 11월 27일 발행분부터 매일 글 규칙을 세 가지 바꿨어요.

| 규칙                             | 예시                                                       |
|----------------------------------|------------------------------------------------------------|
| 소제목 바로 아래 핵심 답 1~2문장 | 이 글의 각 번호 소제목 아래 "한 줄 요약"처럼               |
| 날짜·버전·출처를 명시            | "최근에" 대신 "2026년 11월 25일", "새 버전" 대신 "v24.3.0" |
| 글 끝에 FAQ 2~3개                | 질문형 소제목 + 그 자체로 이해되는 2~4문장 답              |

▶ FAQ 구조 (질문은 h3, 답은 바로 아래 문단)

```
<h2>자주 묻는 질문</h2>
<h3>OO는 무엇인가요?</h3>
<p>OO는 ~예요. 2026년 11월 기준 최신 버전은 ~이고, ~에서 확인할 수 있어요.</p>
<h3>지금 업데이트해야 하나요?</h3>
<p>~를 쓰고 있다면 ~까지 업데이트하는 게 공식 권장이에요. 확인 방법은 본문 3장에 있어요.</p>
```

💡 왜 중요할까

FAQ의 답은 앞의 본문을 안 읽어도 이해되게 써야 해요. AI는 글 전체가 아니라 답 한 덩어리만 떼어서 인용하는 경우가 많아서, "위에서 말한 것처럼" 같은 표현이 들어가면 떼어 낸 문장만으로는 뜻이 통하지 않아요. 이 글 끝에도 같은 형식으로 FAQ를 붙였어요.

## 08 해 보고 느낀 점과 다음 할 일

**한 줄 요약:** 설정 자체는 하루면 끝나고, 효과는 색인이 쌓이는 몇 주 동안 지켜봐야 해요.

막상 해 보니 대부분은 "이미 있는지 확인하고, 비어 있는 걸 채우는" 작업이었어요. 가장 시간이 덜 들면서 확실한 건 블로그 설명 채우기와 검색엔진 등록이었고, 가장 오래 효과가 남는 건 글 구조(FAQ, 핵심 답 먼저)를 매일 규칙으로 만든 거라고 생각해요.

| 언제      | 확인할 것                                                             |
|-----------|-----------------------------------------------------------------------|
| 등록 직후 | 소유확인 성공, 사이트맵 제출 상태가 "성공"인지                        |
| 1~2주 뒤  | 구글 서치 콘솔의 색인 생성 페이지 수, Bing의 색인 수                  |
| 한 달 뒤  | ChatGPT·Perplexity에 블로그가 다룬 주제를 물어봤을 때 출처로 나오는지 |

## 정리

**핵심 1.** 고치기 전에 robots.txt, 사이트맵, JSON-LD, description, h1부터 점검하고, 티스토리가 이미 해 주는 건 그대로 둬요.

**핵심 3.** 구글·Bing·네이버에 등록하고, 글은 "핵심 답 먼저 + 날짜·출처 + FAQ" 구조로 써요.

## 자주 묻는 질문

### GEO는 무엇인가요?

GEO(Generative Engine Optimization)는 ChatGPT, Perplexity 같은 AI 검색이 답변을 만들 때 내 글을 출처로 인용하도록 사이트와 글을 다듬는 작업이에요. 검색 결과 순위를 올리는 SEO와 겹치는 부분이 많아서, 크롤링 허용과 검색엔진 등록 같은 기본 SEO가 먼저 돼 있어야 해요.

### 티스토리에서 AI 크롤러를 따로 허용해야 하나요?

티스토리는 robots.txt를 플랫폼이 관리해서 블로그 주인이 고칠 수 없어요. 2026년 11월 26일에 이 블로그를 점검했을 때는 GPTBot, ClaudeBot, PerplexityBot, Google-Extended를 막는 줄이 없었어요. 내 블로그 주소 뒤에 `/robots.txt`를 붙여 열어 보면 바로 확인할 수 있어요.

### 효과는 언제쯤 확인할 수 있나요?

검색엔진 등록과 사이트맵 제출은 바로 끝나지만, 실제로 색인이 쌓이기까지는 보통 며칠에서 몇 주가 걸려요. 이 블로그는 등록 1~2주 뒤 구글 서치 콘솔과 Bing 웹마스터 도구에서 색인된 페이지 수를 먼저 확인할 계획이에요.
